# Finite movement ingress candidate

This changes only movement packet ownership, not every inbound packet or global tracker ownership. Network movement reaches the existing real PacketDispatcher.onMove once at Connection.channelRead0's sole genericsFtw invocation, after native isOpen and shouldHandleMessage admission and before native packet handling. It requires the current player listener, current session/connection and existing PLAY transport guard. It does not enqueue packet tracking onto the server thread, synthesize movement, change processing order inside PacketDispatcher, or change any detector gate.

The game handleMovePlayer hook no longer dispatches packet tracking. Its authoritative pre-move coordinates are captured immediately AFTER successful PacketUtils.ensureRunningOnSameThread, so only the server replay can update the capture. Existing TAIL event delivery remains separate and unchanged; early-return paths that did not previously reach TAIL are not newly made event deliveries. This keeps a later network HEAD from corrupting the server replay's coordinate capture. Fields remain per-listener and are not a proof against arbitrary same-thread reentrant handleMovePlayer calls.

## Native boundary grounding

check_move_targets.py reads the four cached native jars with javap and retains exact descriptors, admitted channel method, movement handoff prefix, PacketUtils scheduling/throw and PacketProcessor replay bodies under native/. Every native channel method has one genericsFtw invocation after isOpen/shouldHandleMessage. Every movement handler's one ensureRunningOnSameThread has the same descriptor and precedes the first return. The queued packet.handle replay does not enter channelRead0 again. This is native-bytecode source evidence, NOT a woven/runtime result.
