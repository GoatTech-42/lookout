# Headless safety checks

These fixtures test dispatch suppression and log-only side effects without starting Minecraft. They do not qualify mixin registration, packet decoding, a real client, the full released jar, or detection accuracy. Runtime testing remains on hold pending independent review.

Run with Python 3, JDK 25 (`JAVA_HOME`), and the build dependency cache (`GRADLE_USER_HOME`, default `~/.gradle-meshac`):

```
python3 scripts/test_analyzer_cli.py
python3 scripts/test_analyze_deps.py
python3 sim/safety/run_product_safety.py
python3 sim/safety/test_mutations.py
python3 sim/dispatch/run_dispatch_safety.py
python3 sim/dispatch/test_mutations.py
```

## What runs

- Product fixture: the real registered `/mesh kick`, `ban`, `pardon` and `unban` commands through Brigadier. Real Cases persistence, Config loading logic, Discord request guard, Effects containment and Verdict REMOVE run against a temporary case store and Minecraft boundary doubles. It checks log-only leaves stored bans, escalation and connection unchanged; responses identify simulation. Direct case mutation and direct configured-webhook calls are also covered. The isolated ENFORCE fixture proves kick/pardon remain reachable. No HTTP request is sent.
- Dispatch fixture: unchanged production PacketDispatcher, OutboundDispatcher and MoveEventDispatcher bodies, real ContextGate and dependency metadata, synthetic checks and headless boundary doubles. It invokes inbound dispatch, event dispatch, placement, digging plus event, outbound position and movement. World-dependent and unknown checks get zero callbacks; the eligible control executes. The compiled fixture runs from a jar with no source on its runtime classpath. This is not the shipping mod jar with Minecraft's class graph.
- Mutation tests: temporary copies remove each of the four production dispatcher guards, the staff-kick guard, case-add and pardon guards, Discord's egress guard and the veil hold. Each mutation must produce an assertion failure, not a compile failure.
- Analyzer CLI: stale and missing metadata fail `--check` without writing anything. A fresh check passes without Git on PATH. The seeding suite compares generated bytes read-only rather than treating a Git subprocess failure as freshness.

## Limits

The fixtures do not run the Fabric JOIN callback or actual vanilla packet lifecycle. The JOIN source fix still needs integration qualification. They do not prove every effect call site is contained, all callbacks are ordered, or that a suppressed check detects anything. The product fixture uses real Verdict logic but does not connect Vulcan's punishment system to it. That integration remains separate and must preserve upstream decisions.

Recorded evidence is in `docs/build-evidence/2026-11-13-safety-fixtures.log`. The product RED run reproduced staff-kick persistence, pardon/unban mutation, configured-webhook escape and inherited-config veil activation before the fixes. The analyzer RED run reproduced stale `--check` falsely returning success.


## Packet snapshot fixture (not runtime clearance)

Run `python3 sim/world/run_world_snapshot.py` and `python3 sim/world/test_mutations.py`.
They compile the actual production WorldBlockTracker against explicit native/confirmation boundary doubles. They test packet capture timing, recipient independence, signed positions, mutable update copying, reset generations, tile-entity filtering, subsequent updates and radius boundaries. Six realistic source mutations must fail. They do not exercise Minecraft section codecs, shipping adapters/mixins, network acknowledgement ordering, actual check VL/alerts, thread ownership or game sessions. World eligibility stays closed and Veil off. See PARITY.md's packet-owned snapshot entry for limits and the corrected packet serialization timing.
